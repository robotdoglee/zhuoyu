# 琢玉 Zhuoyu

> 如切如磋，如琢如磨。  
> 问渠的姊妹平台：问渠回答「前人做过吗」，琢玉回答「我怎么亲手做一遍」。

琢玉是一个**本地优先**的论文复现工作台：导入一篇论文，拆解方法、补齐背景、排好计划、记录实验、完成复盘。没有后端，所有业务数据都存在浏览器 IndexedDB 里。

当前进度：**M4 打磨、双示例与静态部署准备**。M0 项目骨架、M1 论文拆解与知识框图、M2 计划与实验记录、M3 复盘与成长沉淀、M4 示例与体验优化均已可用；本轮不实际上线，部署平台待定。路线图与验收标准见 [PLAN.md](./PLAN.md)，产品设计见 [DESIGN.md](./DESIGN.md)。

## 已实现（M0）

- **项目**：首页项目列表、新建复现项目（名称、复现目标、L1/L2/L3 级别、设备与算力），刷新后数据仍在。
- **项目详情**：项目概览、论文区与五个工作标签；论文拆解、知识框图、复现计划、记事本和复盘均已可用。
- **论文导入**
  - 上传 PDF：pdf.js 在浏览器内逐页提取文本，显示解析进度，页数、分页文本与文件名存库；可预览每一页。
  - 元数据检索：输入 arXiv ID / arXiv URL 走 arXiv API；输入 DOI 走 OpenAlex。取回标题、作者、摘要、年份、arXiv ID、DOI 等。
  - 可以先检索元数据、之后再补传 PDF；也可以直接上传 PDF，或更换 / 移除论文。
- **本地数据层**：Dexie 持久化项目、论文、文本分块、拆解项、概念及后续里程碑的数据模型。
- **视觉**：与问渠同一套 CSS 变量色板与字体；标题霞鹜文楷（`LXGW WenKai Screen`，npm 包本地打包），正文系统中文无衬线，界面全中文。

## 已实现（M1）

- **文本分块**：按 PDF 页内偏移生成稳定 ID 的文本块，保存页码与起止偏移；支持重新分块，首次生成采用幂等写入。
- **论文拆解**：任务、数据集、模型结构、训练流程、超参、指标与原文数值、算力、代码仓库、补充材料九类事实均可手工增删改。
- **两种抽取方式**：配置 OpenAI 兼容接口后可进行 LLM 结构化抽取（zod 校验、失败重试、单类重抽）；无 Key 时使用纯本地正则启发式，无需外部服务。
- **引文可溯源**：每条拆解保存 `quote + page`，前端归一化匹配原文；不匹配标为「待核实」，可跳转对应页查看原文。
- **知识框图**：React Flow + dagre 展示概念依赖 DAG；支持节点拖拽、画布缩放、自动布局、连线与删边、循环检测，删除节点会同步清理相关依赖。
- **学习路径**：按「会 / 半会 / 不会」记录掌握度，拓扑排序生成必要概念的最短学习路径；标会后即时折叠该节点及已满足的独占前置。
- **分层资源**：按一手论文/官方仓库、教材/Wikipedia、博客/视频分层，后者明确标注「未经同行评审」；支持 Wikipedia、arXiv、GitHub 公开 API 检索及 B 站/知乎搜索跳转。
- **设置与示例**：LLM 地址、模型名和 Key 仅存本机并可一键清除；首页可一键载入「Attention Is All You Need（L2 复现）」示例，含 11 页关键文本节选、16 条示例拆解、10 个概念和 6 条依赖。

## 已实现（M2）

- **三级复现计划**：按 L1 跑通官方代码、L2 复现主表结果、L3 消融/自研生成不同的里程碑、步骤、估时、检查点与前置知识卡片；无 Key 使用本地模板，配置后可调用 OpenAI 兼容接口生成并校验结构化计划。
- **计划编辑与版本**：支持拖拽或按钮排序、增删步骤、修改估时/检查点、待办/进行中/完成/受阻状态流转，全部写入 Dexie；一键按当前进度和概念掌握度重新规划，未掌握前置自动生成学习步骤，旧计划保留为完整只读快照。
- **记事本与计划联动**：按步骤记录命令、代码、结果、报错、想法和截图；支持 Markdown/GFM、@卡片、@步骤及本地截图。保存记录可勾掉检查点并完成步骤，笔记与计划回写在同一事务中提交。
- **指标对照**：录入原文值与实验值，实时计算绝对差和偏差百分比；越高越好/越低越好可配置，结果使用设计规范中的 `--ok` / `--warn` / `--err` 色彩。
- **报错助手**：粘贴日志后提取摘要、关键报错和排查建议，成功时自动写入记事本；未配置 Key 时明确不可用且不发送日志。
- **M2 示例数据**：Attention 示例额外包含 6 步 L2 计划、过程记录和 2 个 BLEU 指标；已有 M1 示例会幂等补齐，不覆盖用户修改。

## 已实现（M3）

- **结构化复盘**：参照 ML Reproducibility Challenge，提供范围、方法、结果、偏差归因总述、数据/超参/随机种子/硬件四类归因、难点与易点、论文没写的细节、与作者沟通等可编辑字段。
- **本地自动汇总**：从项目、论文、拆解、计划、记事本和指标表生成初稿；指标差值与偏差百分比复用指标表的同一计算函数，没有证据的归因保留「待补写」。无 Key 时使用本地模板；配置 Key 后也只有主动点击「LLM 润色」才发送当前复盘文字。
- **论文没写的细节**：记录可标记为隐藏超参、预处理、数据、评估、环境或其他细节，支持修改分类和取消标记；独立专栏与原记录互链，并在复盘中高亮汇总。
- **五种本地导出**：Markdown 含完整复盘、页码、引文与 Mermaid 源码；Obsidian ZIP 为项目、复盘、概念、计划和记录生成真实笔记与有效双链；JSON 保存完整结构化项目数据；Anki CSV 含 UTF-8 BOM、概念正反面和掌握度标签；PDF 报告含中文复盘、指标、引文及渲染后的 Mermaid 知识框图。
- **跨项目技能树**：只累计已掌握概念，同名概念经空白与大小写归一化后只计一次；保留全部来源项目、来源概念和首次掌握时间，以知识图谱和成长时间线展示，并可回溯到原项目。
- **M3 示例数据**：Attention 示例现含一份完整复盘初稿、5 条过程记录及 Adam β₂、句对过滤与长度组批 2 条隐藏细节；补充过程幂等执行，不覆盖用户已有复盘。

## 已实现（M4）

- **两份完整离线示例**：首页可一键载入 Attention Is All You Need 或 Deep Residual Learning（ResNet on CIFAR-10）。两者均内置论文元数据、分页文本、九类拆解、知识框图、过程记录、指标与复盘；Attention 含 L2 计划，ResNet 同时提供 L1 跑通与 L2 复现步骤，并包含数据预处理、残差块、权重衰减等复现要点。示例数据不联网，可单独一键重置，不影响其他项目。
- **统一状态与恢复路径**：通用 `AsyncState` 覆盖首页和五个项目标签的加载、空数据与读取失败状态；空状态给出下一步操作，错误状态提供重试与返回首页。
- **长列表分页**：拆解要素、普通记事本与隐藏细节超过 200 条后按每页 50 条分页，保留筛选状态并避免一次渲染全部内容。
- **大 PDF 解析**：超过 100 页时按 10 页一批解析，每批后通过宏任务主动让出主线程；界面显示当前页/总页数并可取消，取消不会保存半成品。
- **移动端与可访问性**：375px 下首页、五个项目标签、设置和技能树无文档级横向滚动；新建项目、标签切换、检查点和导出控件均可键盘到达，标签支持方向键；按钮、输入、复选框有统一 `:focus-visible` 焦点环，正文和主要按钮对比度不低于 4.5:1。
- **静态路由回退**：Vite `base` 固定为 `/`，同时提供 `public/_redirects` 与 `public/404.html` 两种 SPA 回退；后者通过 `sessionStorage` 恢复原子路由。
- **代码质量**：原有 11 个 React 类 lint 警告已清零，新增 ResNet 示例、分页与大 PDF 分批解析测试。

## 快速开始

要求 Node.js ≥ 20.19（已在 Node 22 验证）。

```bash
cd app
npm install
npm run dev                  # 开发预览，默认 http://localhost:5173
npm test -- --pool=threads   # Vitest：11 个测试文件、35 条用例
npm run build                # 类型检查 + 生产构建，输出 app/dist
npm run lint                 # oxlint 静态检查
npm run preview              # 预览生产构建
```

## 数据与隐私

- 数据库名：`zhuoyu`（IndexedDB），当前 schema 版本 `4`。v2 → v3 保留旧步骤与笔记并补齐计划字段；v3 → v4 只增量补字段：普通记录默认 `isHiddenDetail: false`，已有隐藏记录补默认分类，已掌握概念补掌握时间，旧复盘保留 `deviations` 等原文并补齐 M3 新字段，不清空或重写旧业务内容。
- 十张表及其主要字段：

| 表 | 内容 |
| --- | --- |
| `projects` | 标题、复现目标、级别（L1/L2/L3）、设备与算力、创建/更新时间 |
| `papers` | 论文元数据、来源、页数、分页文本、arXiv ID、DOI |
| `chunks` | 稳定分块 ID、论文与页码、页内起止偏移、文本 |
| `elements` | 拆解项：九类类型、内容、原文引文、页码、来源、校验状态 |
| `concepts` | 概念卡：解释、为何需要、难度、掌握度、最近掌握时间、依赖、画布位置、分层资源 |
| `planSteps` | 计划步骤：里程碑、版本、顺序、估时、状态、检查点、关联概念 |
| `planVersions` | 重新规划前的完整只读计划快照与原因 |
| `notes` | 六类 Markdown 记录、卡片/步骤引用、联动动作、本地截图、隐藏细节标记与分类、来源 |
| `metrics` | 指标：自己的值、论文值、单位、越高越好或越低越好 |
| `retrospectives` | 复盘：范围、方法、结果、偏差总述、数据/超参/种子/硬件归因、难易点、隐藏细节、沟通记录 |

- PDF 文本只在浏览器内解析，业务数据默认不离开本机；截图以 Data URL 存 IndexedDB，单张限制 3 MB，外部 Markdown 图片不会加载。
- 五种导出全部在本机生成与下载，不上传项目内容。Obsidian ZIP、JSON、Anki CSV 直接本地序列化；PDF 使用本地打包的 Mermaid、html2canvas 与 jsPDF 渲染。JSON 包含项目事实与本地截图，不包含 LLM API Key。
- 外部请求仅由论文元数据检索（arXiv / OpenAlex）、公开资源检索（Wikipedia / arXiv / GitHub）或用户主动触发 LLM 拆解、计划生成、报错诊断、复盘润色产生；公开资源检索只发送关键词，LLM 请求只向用户配置的端点发送当前任务所需上下文、日志或复盘文字。
- 未配置 Key 时，计划与复盘使用本地模板，报错助手在构造请求前停止，日志不会发送；LLM 地址、模型名与 API Key 保存在本机 `localStorage`，可在设置页一键清除，不写入项目数据库或导出文件。
- 修改表结构时必须递增 Dexie 版本并补充迁移，避免清空用户数据。

## 论文导入说明

- **PDF**：需带文本层，扫描件暂不支持；单文件 ≤ 80 MB、≤ 300 页（M0 保护阈值）。解析后详情页会显示实际页数、总字数，并可按页查看提取文本。
- **arXiv**：支持 `1706.03762`、`arXiv:1706.03762`、`https://arxiv.org/abs/1706.03762` 等写法。
  - 开发环境通过 [vite.config.ts](./app/vite.config.ts) 中的 `/api/arxiv` 代理访问 arXiv API。
  - 生产构建是纯静态站点。arXiv API 不返回 CORS 头时，浏览器直连会被拦截；此时会自动改用 `10.48550/arXiv.<id>` 经 OpenAlex 取回同一篇论文的元数据，并给出提示。
- **DOI**：如 `10.48550/arXiv.1706.03762`，由 OpenAlex 解析。只发送编号，不发送项目内容。

## M1 使用提示

- 未配置 Key 时直接点击「启发式抽取九类」；配置 LLM 后可切换结构化抽取，也可只对某一类重抽。
- 自动重抽会在确认后替换同类非手工条目，手工新增或编辑过的条目保留；每条结果都应核对引文与页码。
- 知识框图中从节点右侧手柄连到下一概念左侧手柄；点选边后可删除，自动布局与拖拽位置会保存。
- 在学习路径点击「标会」即可观察路径折叠，恢复掌握度后路径会重新计算。
- 再次点击「载入 Attention 示例」会打开已存在的示例项目，不会覆盖你在本机做过的修改。

## M2 使用提示

- 空计划中点击「生成 L1/L2/L3 计划」即可使用本地模板；配置 LLM 后可改用模型生成。拖拽手柄或「↑ / ↓」按钮排序，估时、状态与检查点修改会立即保存。
- 「一键重新规划」会把受阻、进行中、待办步骤排在已完成步骤之前，并按掌握度补充前置学习；通过「查看历史计划版本」打开只读快照。
- 记事本编辑器可插入 @卡片与 @步骤，切换「预览 Markdown」检查排版；保存时勾选「勾掉检查点」「完成步骤」即可回写计划。

## 部署

`npm run build` 产物为纯静态文件（`app/dist`），Vite `base` 为 `/`。由于使用 `BrowserRouter`，部署时必须把未知路径回退到 `index.html`（SPA fallback），否则直接刷新 `/project/:id` 会 404。仓库同时准备两种通用方案，部署平台待定，本轮未实际上线：

- **支持 `_redirects` 的平台**（如 Netlify、Cloudflare Pages）：构建会带上 `dist/_redirects`，内容为 `/* /index.html 200`，直接把所有未知路径重写到应用入口。
- **以自定义 404 页回退的平台**（如 GitHub Pages）：构建会带上 `dist/404.html`。未知路径先进入该页，把当前 path、query 与 hash 暂存到 `sessionStorage`，再返回 `/`；`index.html` 内联脚本用 `history.replaceState` 恢复原地址，随后由 React Router 渲染，刷新后仍停留在原子路由。
- **其他 Nginx / 对象存储**：按平台规则配置 `try_files $uri $uri/ /index.html` 或等价错误页回退；不要同时把 API 或静态资源请求重写到 HTML。

部署后应分别验证首页、直接打开 `/project/:id`、在该地址刷新，以及带 query/hash 的链接。
